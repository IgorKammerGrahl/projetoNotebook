# Dívidas técnicas

Cada dívida tem um teste em `tests/test_debts.py` que fixa o comportamento
**atual**. Quando uma dívida for paga, o teste dela muda junto.

| # | Dívida | Teste | Pagar quando |
|---|--------|-------|--------------|
| DEBT-001 | `.so` de células Mojo editadas nunca são descarregados; acumulam no processo até o kernel reiniciar (~35 KB por versão). | `test_debt_001_old_cell_libraries_stay_loaded` (pelo `MojoRunner` real) | Sessões longas com muitas edições Mojo pesarem em memória. Caminho: reiniciar o kernel sob demanda, ou um processo filho por célula. |
| DEBT-002 | ~~O ponteiro passado ao Mojo não carrega dtype nem strides.~~ **Paga na Fase 2:** o host valida `ndarray`, dtype exato, 1-D, contiguidade e alinhamento antes de passar qualquer ponteiro. | `tests/test_mojo_cells.py::test_invalid_array_inputs_are_rejected_before_mojo_sees_a_pointer` | — |
| DEBT-003 | Mutação in-place não é rastreada. Editar `xs.append(...)` não reexecuta os leitores de `xs`, e reexecutar a célula acumula a mutação. Limite de projeto (D-008). | `test_debt_003_in_place_mutation_is_not_tracked` | Se houver demanda, com detecção de mutação por nome de método ou cópia defensiva. |
| DEBT-004 | Nomes definidos dinamicamente (`globals()[...]`, `exec`) ficam invisíveis ao grafo: não criam aresta nem são apagados. | `test_debt_004_dynamic_names_are_invisible_to_the_graph` | Comparar as chaves do namespace antes e depois de cada célula, se virar problema real. |
| DEBT-005 | `global g` + atribuição dentro de função não conta como definição de `g`; funciona só se a ordem do arquivo ajudar. | `test_debt_005_global_assignment_inside_function_is_not_a_definition` | Tratar `is_declared_global` + `is_assigned` em escopos aninhados como definição. |
| DEBT-006 | Duas células Markdown adjacentes se fundem numa só ao salvar (D-007). | `test_debt_006_adjacent_markdown_cells_merge_on_save` | Fase 3, se o frontend permitir criá-las. Caminho: separador `<!-- cell -->`. |
| DEBT-007 | A captura de saída é global ao processo: `redirect_stdout` nas células Python, e `dup2` dos fds 1 e 2 nas células Mojo, porque o `print` do Mojo não passa por `sys.stdout`. Um `print` de uma thread iniciada pela célula, feito depois que ela termina, vaza para o stdout do kernel. Uma thread do kernel que imprima durante uma célula seria atribuída a ela. | `test_debt_007_thread_print_after_cell_escapes_capture` | Fase 3 (servidor WebSocket em thread): stdout por célula via `contextvars`, ou um processo de execução separado. |
| DEBT-008 | ~~Um crash numa célula Mojo derruba o processo.~~ **Paga (Fase 3):** no servidor, a célula vai para `crashed`, o kernel reinicia e o resto é reexecutado (D-013); a CLI agora também roda pela `Session` (revisão, item 5). | `test_debt_008_paid_cli_survives_a_crashing_mojo_cell` | — |
| DEBT-009 | A interface Mojo só aceita `Int`, `Float64` e arrays 1-D de `float64`, `float32`, `int64`, `int32`. Não há N-D, string, bool nem `PythonObject`. | `test_debt_009_interface_types_are_limited` | **Prioridade (revisão C): arrays 2-D contíguos antes de novos dtypes.** Caminho: shape nos slots. |
| DEBT-010 | **Paga no caminho real (Fase 3, D-014):** a `Session` compila em tarefas assíncronas, paralelas e canceláveis (`tests/test_async_compile.py`), e a CLI usa a `Session`. Continua valendo só no driver síncrono `Engine`, que hoje só existe para os testes semânticos (DEBT-012). | `test_debt_010_compile_blocks_the_caller` (fixa o `Engine`) | Some junto com a DEBT-012. |
| DEBT-011 | O cache em disco (`.nbcache/`) nunca é limpo: cada versão editada de cada célula deixa um `.so` e um `.mojo`. | `test_debt_011_disk_cache_is_never_evicted` | **Revisão C:** LRU por tamanho total do diretório, com limite configurável. |
| DEBT-012 | **Testes semânticos pelo driver síncrono.** ~76 dos 100 testes anteriores à Fase 3 (grafo, células Mojo, dívidas) rodam pelo `Engine`, que executa o `Executor` in-process e lê os valores direto em `e.ns`. A lógica é a mesma do caminho real (scheduler, executor, `mojo`, análise); só 1 deles (`test_debt_010`) cobre algo que existe apenas no driver síncrono. **Mas nenhum deles atravessa a fronteira de processo nem a serialização JSON.** Essa lacuna escondeu um bug real: um preview de array `datetime64` ou complexo matava o kernel e culpava uma célula válida (achado ao passar a CLI para a `Session`). **Regra:** funcionalidade nova é testada só pelo caminho real (`Session` ou WebSocket). O `Engine` não ganha recurso novo. | `tests/test_session.py::test_previews_of_non_json_types_do_not_kill_the_kernel` (o bug que a lacuna escondeu) | Migrar os ~76 testes para a `Session`, com asserções sobre previews em vez de `e.ns`. Aí o `Engine` e o `mojo.build` síncrono podem ser apagados. |
